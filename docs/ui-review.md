# Console UI review

Reviewed October 16, 2026. Scope: starting work, project selection and creation,
project pages, navigation, keyboard interaction, and narrow screens. This review
combines source inspection, a live local preview, and official product references.

## Reference patterns

| Reference | Documented behavior | Application to Warp |
|---|---|---|
| [ChatGPT projects](https://openai.com/academy/projects/) | Projects collect related chats, files and instructions; creation starts from Projects in the sidebar | Use one name for the concept throughout the console; make the selected context visible before sending |
| [Claude projects](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects) | Projects have names and descriptions; standalone chats can be moved into or out of projects | Treat projectless work as a valid choice, show descriptions when choosing context, and keep project identity distinct from presentation |

These are documented reference flows, not claims that Warp duplicates their
interfaces. Warp's useful difference is choosing an answering agent alongside
the project in the composer. Both controls should remain quiet and readable.

## Findings and changes

| Priority | Finding | Result |
|---|---|---|
| High | The prompt bar says No project, which reads as a status rather than an invitation to choose | Untouched state says Select project. Projectless is an explicit choice in the picker and remains visible after selection |
| High | Creating a project requires leaving the prompt bar and finding the sidebar plus | The picker offers Create project, accepts a name and optional description, selects the result, refreshes the sidebar, and keeps the message draft |
| High | Projects are called Areas in navigation and settings, but Project in the prompt bar | Projects is now used throughout the relevant console surfaces, including error messages and storage's Projectless grouping |
| High | At phone widths, an expanded sidebar compresses the main column; a picker anchored beside attachments can extend past the viewport | The expanded sidebar overlays the page with a dismiss control on small screens. The project panel and long labels are bounded to the available width |
| Medium | Project names alone are weak context when several projects have similar names | The picker searches names and descriptions and shows descriptions with each result. Projectless and creation stay available when no result matches |
| Medium | A second form inside the message form could submit a draft when someone searches or creates a project | Project creation uses explicit buttons without nesting forms. Enter in search does not send; Enter in creation validates and creates |
| Medium | Closing a popover through its child callback leaves focus on an element being removed | Popover close now returns focus to its trigger, matching the existing Escape behavior |
| Medium | Translucent project descriptions overlap the greeting and message text | The project panel uses the console's solid panel surface; existing fonts, agent colors and quiet text controls remain |
| Low | Sidebar creation requires discovering that Enter submits the name | Sidebar creation now has a visible Create project button and a pending state |

## Next work

| Priority | Follow-up | Boundary |
|---|---|---|
| High | Project deletion should explain that shared memory is removed and require a deliberate confirmation | Current project deletion is immediate. This pass did not change deletion behavior |
| Medium | Make project and conversation destinations survive refresh and support sharing a direct link | Project selection is local UI state; the address currently returns to the root for project views |
| Medium | Let people edit conversation titles and project display titles | Conversation titles are currently generated by an optional title agent or derived from the first message. Add dedicated update operations and permission checks before exposing edit controls |
| Medium | Configurable console headings and labels | Add optional workspace display configuration with named keys, defaults and plain-text limits. Apply the same values to navigation, headings, empty states and accessible labels. Keep routes, project identifiers, permission names and API fields stable |
| Low | Simplify the first view of workspace tools | Keep starting work and returning to conversations prominent; progressively expose agent administration and operational tools. The Home redesign already in progress is separate from this change |

Display configuration should be workspace-owned, with defaults for missing keys.
It should not rename stored project identities: those currently connect memory,
conversations, schedules and limits. A project display title needs its own field
and API contract. Configuration is a follow-up, not implemented in this pass.

## Verification

  state, and the prohibition on nesting a form inside the composer.
- Live browser: search with no results, Enter in search without sending the draft,

## Project icons and the collapsed rail

Follow-up review: [ChatGPT's official project screenshots](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)
show icons beside project names and a folder-plus creation action.
[Claude's project guide](https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects)
places project navigation in the sidebar. The live Claude page required sign-in;
ChatGPT's live page presented a browser check. The comparison therefore uses
official documentation and the published ChatGPT screenshot, without claiming
to have inspected either signed-in interface.

Warp now uses shared warp folder, open-folder and folder-plus icons in
project navigation and the composer. Projectless work uses a conversation icon.
A folder remains in the collapsed rail and opens a named project list, including
creation when permitted. Opening a project closes the flyout and highlights its
folder. This keeps projects reachable without filling the rail with identical,
unlabelled project icons.

Navigation links reveal text labels on hover and keyboard focus. New conversation
uses a compose symbol, execution history uses a history symbol, the sidebar
toggle shows its opening or closing direction, and collapsed Settings uses a
gear. Home remains directly reachable in both sidebar states. The shared icons
and tooltip live in `packages/render-web`.

Verified in the local browser: collapsed project navigation, selection and active
state, keyboard opening and Escape focus restoration, keyboard tooltip labels,
and a 390-pixel viewport with no horizontal overflow. A regression covers the
collapsed Projects entry and project-creation permission.

## A flatter sidebar, after Claude's desktop app

Follow-up review against Claude's desktop app, from a screenshot of its signed-in
sidebar: a short flat list (New, Projects, Artifacts, Scheduled, Customize,
More), then Pinned, then Chats and tasks. Warp's sidebar had Home and New
conversation side by side, though both open the same empty conversation, and two
labelled groups of eight tools under the task list.

Warp now follows the same shape:

- **New** is home. The separate Home entry is gone, and New is current on the
  empty conversation at the bare address.
- **Projects** opens a page of project cards with a New Project button, instead
  of an expanding list in the sidebar. Deleting a project returns to it.
- **Inbox** and **Scheduled** stay at the top level, since people use them daily.
- **More** folds Agents, Knowledge, Storage, Evals, Execution history, Analytics
  and Alerts. It stays open while one of its pages is on screen, shows a dot when
  an alert is waiting, remembers its state per browser, and is a flyout in the
  collapsed rail.
- **Pinned** holds conversations a person pins from the pin beside each task.
  Pins are saved with their preferences (`pinned` on `PUT /api/preferences`), so
  they follow the person to another browser.
- **Tasks** rows are one line: the agent's orb and the title, with the state and
  project in the row's tooltip and read out to screen readers.

Verified in the local browser with `make dev`: pinning, a pin surviving a
reload, More open and folded, the Projects page, and the collapsed rail.

## One console for agents across systems

Second pass, after the first one above. Warp is a place to run work with agents,
project by project, so the navigation follows the work rather than the
platform's parts.

- **Sidebar order:** New, Projects, Schedules, Alerts, Inbox, Knowledge,
  Agents, Artifacts, then Pinned and Tasks. There is no More menu.
  - Execution history leaves the sidebar: each task already holds the history
    of every run in it, and a run anywhere opens its task.
  - Evals live on the agent or knowledge source they test.
  - Analytics is the Overview tab of Alerts, next to the rules that watch it.
  - Storage is named Artifacts.
- **Deep links:** every page, tab and selection is a path, such as
  `/agents/lead/access` or `/knowledge/handbook/evals`, and back and forward work.
- **One page layout:** one centered column with a back link, a title and meta
  line, actions on the right, and tabs that stay in view while scrolling.
- **Agents:** Prompt, Model, Access, Knowledge, Memory, Evals, Alerts and
  Revisions tabs.
  - The model is a policy: a primary and ordered fallbacks.
  - Agents it may call, and sources it reads, are picked from a searchable list.
    A switch per agent did not scale.
  - Approving a call to another agent is no longer offered. Agents call through
    one host tool, so that approval named a tool the agent never held, and the
    agent could not start.
- **Alerts:**
  - Rules can be edited and paused.
  - They can be scoped to a project, notify chosen people and roles, wait out a
    cooldown, and watch spend.
- **Schedules:** each one has a page with its upcoming times and recent runs,
  and it can be edited without losing either.
