# Choose references for Humagen's working interface

**Use Harvey II for workspace structure, Codex for supervising agent work, and Linear for interaction consistency.** That is one reference direction for Humagen: a professional place where projects, people, agents and decisions remain connected. Add Claude and Dust for interaction judgment, Figma for managing complex tool states, and Raycast for frequent actions. These are selected for relevance and documented shipped work, not ranked as the world's best designers. ## Harvey II changes the workspace, not only its styling

The strongest verified match for “Harvey v2” is **Harvey II**, announced **18 August 2026**. The product places documents, parties, tasks, permissions and history in a matter or project Space, with work moving between lawyers and agents. That makes it particularly relevant to Humagen's shared-project model. ([Official introduction](https://www.harvey.ai/blog/introducing-harvey-ii))

The separately dated **14 October 2026 UI refresh** introduces direct Agents access, a redesigned sidebar, a consolidated Library, easier return to recent work and Spaces, and notifications that lead to work requiring attention. These are useful structural references: find work, understand its context, return to it and act. They are documented product changes, not inferred token measurements. ([Official release notes](https://eu.help.harvey.ai/release-notes), [experience release index](https://eu.help.harvey.ai/release-notes/category/user-experience))

Do not confuse either release with the **16 January 2026 design-system rebuild**. Christopher Sim, Stephanie Yeung and Brian Nelson describe shared design/engineering vocabulary, tokens named for intent, and foundations that support additional themes and surfaces. Their contribution is a systems reference. Farsai and Rostad's separate November 2025 essay is the stronger source for product judgment and human oversight. ([System rebuild](https://www.harvey.ai/blog/rebuilding-harveys-design-system-from-the-ground-up), [product-design principles](https://www.harvey.ai/blog/how-we-approach-design-at-harvey))

## Codex and Dust explain how to design agent work

Codex's February 2026 launch organizes parallel agent threads by project, connects output to contextual review, and returns scheduled work through a review queue. Study the transition from execution to human judgment, including continuity with existing work. Bayes's original interview adds the underlying rationale: people need understandable approvals and mode choices, while the composer must reveal capabilities without overwhelming them. ([Codex app launch](https://openai.com/index/introducing-the-codex-app/), [Bayes interview](https://softwareengineeringdaily.com/wp-content/uploads/2026/01/SED1898-OpenAI.txt))

Dust adds a useful principle: **human-agent symmetry**. A detailed organizer's account of Wautier's September 2026 discussion describes capabilities that people can control through the interface and agents through textual/API primitives. This is attributed discussion evidence, not a published Dust-wide manifesto. For Humagen, the implication is that people should recognize and understand the same operations that agents perform. ([TPC discussion summary](https://tpc-recrutement.com/ressources/conseils/futur-equipes-design-ia-dust))

Wautier's first-person February essay is especially practical: run the interaction with realistic content, errors, empty states and keyboard behavior before settling visual polish. Claude's designers provide a compatible judgment standard: prototype cheaply, understand both user needs and the technical medium, and introduce specialized controls when they solve an actual problem. ([Wautier](https://dust.tt/blog/field-study-prototypes-over-mockups), [Parrott](https://www.aidesignfieldguide.com/articles/nate-parrott))

## Five Humagen criteria follow from these references

The following criteria are **our synthesis**, not quotations or official requirements from these companies.

| Criterion | A concrete question for evaluating a design | Research basis |
|---|---|---|
| **Organize around work** | Can someone find the project, its context and the active work without understanding the runtime architecture? | [Harvey II](https://www.harvey.ai/blog/introducing-harvey-ii), [Linear's workbench](https://linear.app/now/design-for-the-ai-age) |
| **Make human decisions visible** | Can they distinguish running work, blocked work and completed output awaiting review, then act in context? | [Codex launch](https://openai.com/index/introducing-the-codex-app/), [Harvey release notes](https://eu.help.harvey.ai/release-notes) |
| **Reveal control where it matters** | Are permission, approval and stop choices understandable at the consequential step? | [Bayes interview](https://softwareengineeringdaily.com/wp-content/uploads/2026/01/SED1898-OpenAI.txt), [Figma's UI case](https://rsms.me/work/figma/) |
| **Use one interaction vocabulary** | Do people recognize the same action and outcome across projects, conversations and agent operations? | [Dust discussion](https://tpc-recrutement.com/ressources/conseils/futur-equipes-design-ia-dust), [Harvey's system rebuild](https://www.harvey.ai/blog/rebuilding-harveys-design-system-from-the-ground-up) |
| **Prove the complete interaction** | Does the design work with waiting, refusal, cancellation, recovery and real evidence, including exact costs? | [Wautier's method](https://dust.tt/blog/field-study-prototypes-over-mockups), [Aupiais on data trust](https://medium.com/algolia-design/building-trust-with-data-visualisation-13321b44b819) |

Linear is the strongest additional reference for keeping that system coherent as features accumulate. Figma contributes explicit evidence of simplifying repeated controls while preserving effective structure. Raycast contributes a narrower lesson: shortcuts become useful to more people when the interface makes them visible. These are complementary jobs within the recommended direction. ([Saarinen](https://karrisaarinen.com/posts/every-feature-should-earn-its-place/), [Figma refresh](https://www.figma.com/blog/ui-refresh/), [Raycast refresh](https://www.raycast.com/blog/a-fresh-look-and-feel))

## Keep attribution and evidence limits visible

**Product UI and brand work are separate reference tracks.** Geist documents Anthropic's launch-era identity and digital work. Harvey's foundational brand case credits Geist's Eric Mortensen and Tim Kamerer, while Farsai describes himself as the internal stakeholder. These sources support studying visual expression; they do not establish authorship of every current product screen. Dust's public `PRODUCT.md` is likewise explicitly a marketing/brand brief, not a universal product-UI rulebook. ([Geist's Anthropic case](https://geist.co/work/anthropic), [Harvey brand credits](https://www.shawnfarsai.com/work/harvey-brand), [Dust brand brief](https://github.com/dust-tt/dust/blob/main/PRODUCT.md))

**Exact individual Harvey II refresh credits remain unverified.** The same applies to sole authorship of Dust Pods and exhaustive Codex screen credits. Several portfolio links are professional profiles rather than visual case studies. Jenny Wen's own current bio uses past tense; Ian Silber is a historical ChatGPT/Codex design reference rather than a current leader, and Rasmus Andersson's case covers UI2 rather than today's Figma UI3. ([Jenny's site](https://jennywen.ca/), [Ian's departure statement mirror](https://teapawt.net/iansilber), [Rasmus's dated case](https://rsms.me/work/figma/))

The research verifies public credits, writing and product announcements through **26 October 2026**. It does not constitute a live visual audit, usability comparison or accessibility assessment of Humagen or these products. The shortlist is ready for selecting reference interactions; pixel-level rules would require inspecting the actual screens and their states.
